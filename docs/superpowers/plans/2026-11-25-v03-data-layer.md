# v0.3 数据层实施计划（schema v2 + 任务仓库扩展）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-subagent-driven-development (recommended) or superpowers-executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** schema v1→v2（Tasks 增 4 列）+ TaskRepository 新查询/状态流转/重排/重复生成 + 导出往返。为视图/调度/交互提供数据地基。

**Architecture:** Drift 迁移注册表（`migrationSteps` 下标 0 = v1→v2）+ `dart run build_runner` 重跑生成器；重复规则用独立模型 `RepeatRule`（`daily/weekly/monthly/every:N`）；完成时事务内克隆副本。

**Tech Stack:** Flutter、Drift 2.20、SQLite。

**Spec:** `docs/superpowers/specs/2026-11-25-v03-data-layer-design.md`

### Task 4: complete() 事务内生成下一次

**Files:**
- Modify: `lib/data/repositories/task_repository.dart`

- [x] **Step 1: 抽 insert 内部助手**

把 `create` 里插入+绑标签的逻辑抽为私有 `Future<int> _insertTask(TaskDraft draft)`，
`create` 复用之（保持行为不变）。

- [x] **Step 2: complete 事务**

`complete(id)` 改为事务：

1. 读任务（含标签 id 列表）
2. 原任务写 `status=done, completedAt=now`
3. 若 `RepeatRule.parse(task.repeatRule)` 非 null：
   - 构造克隆 draft：title/notes/projectId/contextId/energy/priority 原值；
     `status=nextAction`；`scheduled`/`dueDate` 非 null 则各自 `nextDate` 推进；
     `reminderAt` 同推进；`repeatRule` 保留；无 waitingOn
   - `_insertTask(克隆)`（标签同步绑定）
   - 新副本 `sortOrder` 取 `(SELECT MAX(sortOrder)+1 FROM tasks)`
