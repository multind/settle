# FAB 按页互斥设计（修复「+按钮语义混乱」）

日期：2026-11-25
状态：已批准（用户确认设计）
前置：Windows 发布安装包 v0.1.1 已收官（HEAD `d695d69`，工作区干净）

## 1. 背景与问题

用户验收反馈：应用里"很多地方的 + 按钮都是收集"。经代码确认，根因是**嵌套 Scaffold
导致 FAB 叠加**：

- 外壳层（`ResponsiveShell`）对所有非收件箱页统一显示全局收集 FAB
  （`global_collect_fab`，点击弹收集框入库收件箱）。
- 项目页/情境页/回顾页自身 Scaffold 各带一个新建 FAB
  （`new_project_fab` / `new_context_fab` / `new_review_fab`）。
- Flutter 嵌套 Scaffold 时两个 FAB 同时渲染、位置重叠，语义混淆。

## 2. 目标

每个页面右下角**只出现一个 FAB**，其语义与页面一致：可新建的页显示"新建"，
不可新建的页显示"收集"。

## 3. 方案：按页互斥

| 页面（外壳下标） | 修改后显示的 FAB | 语义 |
|---|---|---|
| 收件箱（0） | 无（顶部内嵌快速收集框） | 收集入口已内嵌 |
| 今日（1）/ 等待（4）/ 将来也许（5） | 全局收集 FAB（现状保留） | 无新建语义，+ = 收集 |
| **项目（2）/ 情境（3）/ 回顾（6）** | **仅页面自己的新建 FAB**，隐藏全局收集 FAB | + = 新建项目/情境/回顾 |
| 设置（7） | 全局收集 FAB（现状保留） | 与现状一致，不扩大改动 |

## 4. 实现（单文件改动）

**`lib/app/responsive_shell.dart`**：外壳 FAB 显示条件从 `_index != 0` 改为
`_index != 0 && !const {2, 3, 6}.contains(_index)`（2=项目、3=情境、6=回顾）。

各页面自身 FAB 不动；收集对话框、新建对话框、窄屏导航项均不动。

## 5. 测试

**修改 `test/widget/responsive_shell_test.dart`**：

1. 新增断言①：切到情境页后 `new_context_fab` 存在、`global_collect_fab` 不存在。
2. 新增断言②：切到今日页后 `global_collect_fab` 存在（回归现状）。
3. 现有「非收件箱页全局 FAB 一步收集」测试用今日页，不受影响；全量 `flutter test`
   保持 96/96。
4. `flutter analyze` 0 error。

## 6. 范围外（明确不做）

- 不改各页新建对话框与收集对话框逻辑
- 不改窄屏导航 5 项
- 不改 FAB 外观/视觉
- 不引入 FAB 弹出菜单（已否决的方案）

## 7. 验收

- 项目/情境/回顾页：右下角只有新建 FAB，点它弹对应新建对话框
- 今日/等待/将来也许/设置页：右下角只有收集 FAB，点它弹收集框
- 收件箱页：无 FAB，顶部快速收集框照常
